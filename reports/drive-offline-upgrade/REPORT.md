## الأخطاء التي أُصلحت

1. التعبير الخاص بـversionCode كان يستخدم شرطات مائلة مضاعفة داخل raw string، فيبحث عن نص حرفي بدل حدود الكلمات والأرقام. ظهر الخطأ عند تشغيل الاختبارات قبل أي تعديل.
2. قارئ شهادة APK كان يقبل صيغة Signer #1 فقط؛ يدعم الآن صيغة V3.0 Signer الحالية، ويشترط موقّعًا واحدًا وتطابق SHA-1 وSHA-256 وتوقيع v2 صالحًا.
3. لم تكن شهادة النسخة المثبّتة تُفحص. تُنسخ الآن نسخة مؤقتة من APK المثبّت على المحاكي فقط، وتُفحص قبل حفظ baseline وقبل التحديث وبعده. لا تُنسخ بيانات حساب أو صوت من الهاتف.
4. صُحّح تمرير أوامر run-as ومسارات الملفات إلى shell البعيد باستخدام quoting صريح وقائمة مسارات مفصولة بـNUL، لمنع فساد المسارات ذات الفراغات. المسارات غير المتوقعة تُرفض بدل إسقاطها بصمت.
5. لم يعد ملف صوتي فارغ يكفي لإنشاء baseline. وحُمي ملف الدليل من الاستبدال بإنشاء حصري وصلاحية 0600.
6. أضيف حد زمني لأوامر الجهاز، وأُزيل نسخ تشخيصاتها الخام إلى رسائل الخطأ. بقي منع الهاتف الفعلي، والتحقق من الجهاز والإصدار والملفات قبل install -r، وعدم مسح البيانات أو حذفها.
7. صارت رسالة النجاح FILE PRESERVATION PASS صريحة في حدودها؛ لا تزعم نجاح التشغيل أو حل مشكلة فقدان علامة التنزيل.

## فحص APK الأصليين

## عائق الاختبار الكامل

الفحص الفعلي للمضيف لم يجد `adb` أو `emulator` أو `sdkmanager` أو `avdmanager` أو `aapt` أو برنامج `apksigner` على PATH. لم يجد أيضًا مجلد AVD في المسار القياسي أو Android SDK في المسارين المفحوصين. وُجد Java وملف apksigner.jar مستقل، وهو كافٍ لفحص توقيع APK دون محاكي.

محاولة تشغيل مرحلة baseline فعليًا توقفت بأمان عند غياب executable `adb`، قبل إنشاء baseline أو إجراء أي تثبيت. [سجل المحاولة](emulator-attempt.txt) · [جرد البيئة](environment.json).

لم يوجد `/dev/kvm` أيضًا؛ غيابه وحده لا يثبت استحالة محاكي برمجي، لكن المحاكي وADB غير متاحين أصلًا في هذه البيئة. لذلك لم يُنشأ اتصال بحساب Google ولم يُستخدم حساب المستخدم الحقيقي أو ملفه الصوتي كبديل لحساب الاختبار.

لا تثبت الاختبارات الـ21 بقاء ملف صوتي حقيقي عبر تحديث Android، ولا تثبت إمكانية تشغيله دون إنترنت أو استرجاع مساحة الحساب ومعرّف الملف في التطبيق. لم تُنتَج نتيجة نجاح لتلك المراحل، ولم يُخمّن سبب المشكلة.
